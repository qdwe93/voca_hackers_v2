# P1 — 콘텐츠 + 이미지 프롬프트 (외부 AI 3개에게 각각)

DAY 01~30 전체를 **한 단계로** 끝낸다. 같은 범위를 Claude Opus · GPT Sol · Gemini
에게 각각 시키고, 나중에 세트별로 제일 나은 것을 골라 승격한다.

산출물은 저장소에 텍스트로만 쌓인다:

```text
content/candidates/<author>/DAYnn_ss-ee_setn/words.json
content/candidates/<author>/DAYnn_ss-ee_setn/image_prompts.md
```

`<author>` 는 `opus` / `sol` / `gemini` 셋 중 하나다.

## 외부 AI 에게 그대로 붙여 넣는 요청문

아래 블록을 통째로 복사해 각 AI 에게 준다. `<author>` 와 DAY 범위만 바꾼다.
전체 범위를 요청하되 기존 파일을 건너뛰며 이어서 작업할 수 있게 한다.

```text
작업 폴더는 C:\Workspaces\english\hackers_video_project_v2 하나뿐이다.
다른 폴더는 열지도 쓰지도 마라.
시작 전에 PLAN.md 와 prompts/P1_콘텐츠_이미지프롬프트.md 와 req.txt 를 읽어라.

DAY 01~30 의 120개 세트에 대해 words.json 과 image_prompts.md 를 만들어라.
저장 위치는 content/candidates/opus/DAYnn_ss-ee_setn/ 이다. (opus 자리에 네 이름을 쓴다)
이미지는 생성하지 마라. 이 단계는 텍스트만 만든다.

words.json 규칙:
- schemaVersion 3, day/range/set 은 폴더명과 일치
- 단어 10개는 hackers.csv 의 해당 DAY·번호 순서 그대로
- 각 단어: no, word, partOfSpeech(n. v. adj. adv. 등), meaningKo(품사 빼고 간결하게),
  ipa(미국식, /슬래시/로 감싼다), definition(초등 6학년 수준 영영풀이, 12단어 이하),
  sentence(표제어 철자 그대로 포함, 8~12단어, 눈에 보이는 장면),
  wordImage: images/{2자리번호}_{소문자단어}_word.png,
  sentenceImage: images/{2자리번호}_{소문자단어}_sent.png,
  speaker: 세트 내 위치 1·2·3·4 순환으로 Zephyr, Liam, Erinome, Charon (5번째부터 다시 Zephyr)
- 동형이음어·다품사어는 발음과 품사를 교차 확인해라 (예: 명사 wound 는 /wuːnd/)
- 예문끼리 이야기를 잇지 마라. 고정 인물 이름을 반복하지 마라.
- 나쁜 뜻의 단어도 판타지·동물·게임 표현으로 안전하게 만들어라 (req.txt 기준)

image_prompts.md 규칙 (짧게 쓰는 것이 핵심이다):
- 세트당 20개. "## 파일명" 다음 줄에 프롬프트 한 문장.
- 형식: <장면 묘사 영어 한 문장> + 고정 접미
  단어 이미지 접미: Stylized 3D cartoon illustration, square. No text.
  예문 이미지 접미: Stylized 3D cartoon illustration, wide. Main subject in the upper two thirds. No text.
- 장면 묘사는 30단어 이하 (하드 상한 45단어). 짧을수록 좋다.
- 비율, 해상도, 하단 여백, no logo, no watermark, no badge, 화풍 수식어를 넣지 마라.
  약한 이미지 모델이 그런 지시를 받으면 피사체를 자르거나 화면을 단색으로 채운다.
- 단어 이미지는 그 단어 자체를 알 수 있는 장면, 예문 이미지는 예문 문장의 장면이다.

다 만들고 나서 반드시 통과시켜라:
  node remotion\scripts\validate-content.mjs --author opus
FAIL 이 남아 있으면 고치고 다시 돌려라. 통과한 상태로 끝내라.
작업이 끝나면 content/candidates/opus/run_report.md 에 만든 범위·세트 수·검증 결과를 기록해라.
```

## 고르기와 승격 (로컬)

```powershell
node remotion\scripts\validate-content.mjs --author opus
node remotion\scripts\validate-content.mjs --author sol
node remotion\scripts\validate-content.mjs --author gemini

node remotion\scripts\compare-candidates.mjs --set DAY01_01-10_set1 --out compare_DAY01_set1.md
node remotion\scripts\promote-candidate.mjs --author sol --set DAY01_01-10_set1
node remotion\scripts\promote-candidate.mjs --author opus          # 남은 세트 일괄
```

- `compare-candidates` 는 IPA·뜻·정의·예문을 단어별로 나란히 놓은 표를 만든다.
  **판단 기준: IPA 정확도 → 정의가 초6 수준인가 → 예문이 그림으로 그려지는가.**
  스크립트는 형식만 본다. 의미 오류는 사람이나 상위 모델이 잡아야 한다.
- 승격은 검증을 통과한 후보만 가능하며, 이미 승격된 세트는 `--replace` 없이 덮지 않는다.
- 세트마다 다른 author 를 골라도 된다 (세트 안에서만 일관되면 된다).
