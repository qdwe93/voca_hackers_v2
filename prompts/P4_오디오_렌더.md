# P4 — 오디오·렌더 배치 (로컬, 무인)

이미지가 다 차면 남은 일은 전부 스크립트다. 사람이 볼 것은 마지막 요약뿐이다.
120세트 콜드 환산은 TTS 약 3.8시간 + 렌더 약 4.6시간이다. 밤에 돌린다.

## 실행 순서

```powershell
node remotion\scripts\status.mjs

& C:\Workspaces\tts\qwen3_tts_1.7b_base\.venv\Scripts\python.exe tts\build_set_audio.py --all

node remotion\scripts\check-assets.mjs
node remotion\scripts\render-batch.mjs
```

- `--all` 은 `words.json` 이 있고 `narration.mp3` 가 없는 세트만 처리하며 **모델을 한 번만
  로드한다.** 세트마다 따로 실행하지 않는다.
- `check-assets.mjs` 는 인자 없이 실행하면 승격된 세트 전부를 검사한다.
- `render-batch.mjs` 는 게이트를 통과했고 MP4 가 없는 세트만 렌더한다. `--filter DAY07`
  로 범위를 좁힐 수 있다.
- 중간 실패 세트는 건너뛰고 계속 간다. 마지막 표에 모아서 나온다.

## 실패 대응

| 증상 | 원인 | 조치 |
|---|---|---|
| `audio_report.json` overflow > 0 | 정의·예문이 슬롯보다 길다 | 그 단어의 `definition`/`sentence` 를 짧게 고치고 (`validate-content.mjs` 재통과) 그 세트의 `narration.mp3` 와 `audio_report.json` 을 지운 뒤 다시 빌드 |
| `stretchRatio` 가 0.85~1.2 밖 | 낭독 속도가 정책 범위를 벗어남 | 보고만 한다. 격자·속도 상수는 사용자 지시 없이 바꾸지 않는다 |
| `FAIL asset gate` | 이미지 규격·개수·narration 길이 | `check-assets.mjs` 출력의 세트만 P2 로 되돌린다 |
| 렌더 실측이 192.853±0.1초가 아님 | 타이밍·자산 불일치 | 실패 MP4가 격리되므로 원인을 분석한다 |

같은 단계를 3회 실패하면 멈추고 `handover.md` 에 적는다. 무한 재시도 금지.

## QA (렌더된 세트마다)

`render-batch.mjs`가 아래 QA를 자동 실행한다.

- ffprobe: H.264 비디오 + 오디오 스트림, 192.853±0.1초, 5,784프레임
- 각 단어 블록 +5초(학습) / +13초(예문) 프레임 20장을 `remotion still`로 추출
- contact sheet 로 학습 화면 10개·예문 화면 10개의 가독성과 자막 겹침 확인
- 첫 화면 전환 11.9초 전/중/후 프레임에 빈 화면이 없어야 한다
- 첫 예문 화면 11.9초 → 첫 예문 발화 13.4초 (약 1.5초 화면 선행)
- 오디오 스팟체크: 2.4초(Zephyr), 13.4초(첫 예문), 21.4초(Liam 교체)

전량 QA 는 현실적으로 불가능하다. **세트 10개당 1개를 표본으로 보고**, 나머지는
ffprobe 수치와 contact sheet 자동 생성 결과만 확인한다. 표본에서 문제가 나오면
그 DAY 전체를 본다.
