# P1 — 공통 교과 개념 배정

## 목적

`word_inventory.jsonl`의 1,200단어에 중학교 1학년 교과 개념을 **한 번만 공통 배정**한다.
이 결과는 `codex`, `antigravity`, `claude`가 예문을 만들 때 함께 사용하는 고정 입력이다.
세 모델이 각자 개념을 다시 고르게 하지 않는다.

이 단계에서는 영어 예문을 만들지 않는다. 단어의 뜻·품사·영영 정의를 고치지도 않는다.

## 작업 경계

- 쓰기 허용: `mid1st/data/concept_assignments.jsonl`, `mid1st/data/concept_usage.json`, 필요한 임시 파일,
  `mid1st/reports/assignment-validation.md`
- 읽기 전용:
  - `mid1st/data/word_inventory.jsonl`
  - `mid1st/data/concept_catalog.json`
  - `mid1st/data/sets/`
  - `part_day_table.md`
  - `hackers.csv`
  - `content/candidates/final/`
  - `C:/Workspaces/junbe_study/middle_1st/content_eng/`
- 기존 원본과 이미 완성된 배정 파일을 덮어쓰지 않는다. 완성된
  `mid1st/data/concept_assignments.jsonl`이 있으면 임의로 다시 만들지 않는다. 배정은 유효하고
  사용량 파일만 없으면 배정 재생성 없이 누락된 사용량 파일만 만든다. 둘 다 완성됐으면
  검증 결과만 보고한다.

## 절대 고정 입력

각 단어의 다음 값은 확정본이다.

- `wordId`, `day`, `no`, `set`, `word`
- `partOfSpeech`, `meaningKo`, `ipa`, `definition`
- PART·DAY 번호와 주제

철자, 뜻, 품사, 정의가 마음에 들지 않아도 변경하거나 다른 뜻으로 해석하지 않는다. 특히
다의어는 `meaningKo`와 `definition`이 가리키는 그 뜻만 사용한다. 배정 결과에는 고정 의미
필드를 다시 쓰지 않고 불변 identity만 복사한다.

## 매칭 우선순위

아래 순서는 바꿀 수 없다.

1. 확정된 `meaningKo`, `partOfSpeech`, `definition`과 의미가 정확히 맞는가
2. 교과 개념과 단어가 직접적이고 문자 그대로 연결되는가
3. 그 교과 개념을 사실에 맞게 관찰·측정·분류·설명하는 장면을 만들 수 있는가
4. 같은 품질의 후보끼리는 현재 사용 횟수가 더 적은 개념인가
5. DAY 주제, 그다음 PART 주제와 자연스럽게 맞는가
6. 정직한 교과 연결이 없으면 fallback을 쓰는가

사용 횟수는 **동일하게 정확하고 선명한 후보 사이의 동률 결정 기준**일 뿐이다. 빈도가 낮다는
이유로 약한 개념을 붙이지 않는다. 153개 개념을 모두 쓰는 것은 목표가 아니며 강제 할당도
금지한다.

## 허용하는 `matchMode`

| 값 | 조건 | `conceptId` |
|---|---|---|
| `direct` | 단어 자체가 해당 개념의 핵심 대상·행동·성질·관계를 직접 나타낸다 | 유효한 ID |
| `contextual` | 단어를 문자 그대로 쓰는 행동·상태가 해당 개념을 실제로 관찰하거나 설명한다. 개념은 장식이 아니라 문장 의미에 필요하다 | 유효한 ID |
| `day_fallback` | 정직한 교과 개념 연결은 없지만 확정된 DAY 주제로 직접적인 장면을 만들 수 있다 | `null` |
| `word_fallback` | 교과 개념이나 DAY 주제보다 단어 자체의 자연스러운 문자적 장면이 더 정확하다 | `null` |

다음은 `contextual`로 인정하지 않는다.

- 아무 단어에나 “과학 시간에”, “수학책에서”, “사회 수업에서”를 덧붙인 문맥
- 개념 용어가 배경에만 있고 단어와 사실 관계가 없는 문맥
- 비유·은유·상징·의인화·말장난으로 만든 연결
- 어려운 전문용어를 끼워 넣었지만 학생이 관찰할 수 있는 사실이 없는 연결
- 단어의 확정된 뜻이 아닌 다른 사전을 사용한 연결

약한 `contextual`보다 `day_fallback`이 낫고, 억지 DAY 연결보다 `word_fallback`이 낫다.

## 배정 절차

### 1차 — 의미 적합 후보 찾기

각 단어마다 먼저 고정 뜻과 품사를 확인하고, 카탈로그에서 실제로 가능한 개념만 후보로
고른다. 후보마다 아래를 내부적으로 확인한다.

- 단어가 그 장면에서 확정 뜻 그대로 쓰이는가
- 교과 개념을 문장 한 줄에서 직접 확인할 단서가 있는가
- 중1 수준에서 사실로 맞는가
- 한 장면으로 보이거나 한 번의 관찰·측정·분류·행동으로 이해되는가
- 안전 규칙을 지킬 수 있는가

후보가 없으면 즉시 fallback을 허용한다. 그럴듯해 보이는 개념을 새로 꾸며내지 않는다.

### 2차 — 사용량을 보며 선택

처리 중 `conceptId`별 현재 사용 횟수를 계속 집계한다. 의미 정확성·직접성·사실성·장면
선명도가 사실상 같은 후보가 둘 이상일 때만 사용 횟수가 가장 적은 개념을 고른다.

단어 순서 때문에 초반 개념이 유리해지지 않도록 DAY 하나를 끝낼 때마다 누적 빈도를
검토한다. 개념을 바꿀 때에도 `direct`를 약한 `contextual`로 낮추지 않는다.

### 3차 — 전량 균형 검토

1,200개 초안을 만든 뒤 다음 검토를 한 번 더 한다.

1. 사용 0회 및 하위 사용 개념을 찾는다.
2. 사용량이 큰 개념의 배정 중, 동등하게 정확한 대안이 있었던 항목만 다시 본다.
3. 덜 사용된 개념으로 옮겨도 단어 뜻·직접성·사실성·장면 선명도가 떨어지지 않을 때만
   재배정한다.
4. 옮길 만한 단어가 없으면 해당 개념은 0회 또는 낮은 빈도로 그대로 둔다.
5. fallback도 교과 개념으로 억지 전환하지 않는다.

실제 평균은 `conceptId`가 있는 교과 배정 수를 153으로 나눈 값이다. 1,200개를 전부 교과에
배정했을 때의 약 7.8회는 이론상 최대 참고치일 뿐이며, 목표 할당량이나 상·하한이 아니다.

## `conceptCueKo` 작성법

`conceptCueKo`는 다음 단계가 예문에 반드시 구현할 **구체적 사실·관찰·연산·관계**를 짧은
한국어로 적는다. 단원명 반복이나 추상적 지시로 끝내지 않는다.

- 좋음: `같은 크기의 물체를 저울에 올려 질량을 비교한다`
- 좋음: `전체 점수의 합을 자료 수로 나누어 평균을 구한다`
- 나쁨: `수학과 연결한다`
- 나쁨: `흥미로운 과학 장면을 만든다`

`day_fallback`이면 DAY 주제에서 보여줄 직접 장면을, `word_fallback`이면 단어 뜻을 가장
선명하게 보여줄 문자적 장면을 적는다. 이 필드는 예문 초안이 아니므로 영어 문장을 쓰지
않는다.

## 검토 표시

다음 중 하나라도 해당하면 `reviewRequired`를 `true`로 하고 `reviewReason`에 구체적인 이유를
한 문장으로 쓴다.

- 고정 뜻이나 품사의 대표 용법을 한 장면에 쓰기 까다롭다
- 두 개념이 실제로 동률이라 사람이 방향을 정하면 품질이 크게 달라진다
- 교과 사실의 범위나 표현에 주의가 필요하다
- 연결이 장식적으로 보일 위험이 있다
- 안전하게 표현하면서 뜻을 유지하기 어렵다
- `confidence`가 `low`다

검토가 필요 없으면 `reviewRequired: false`, `reviewReason: ""`로 쓴다. fallback이라는
이유만으로 무조건 검토 대상으로 만들 필요는 없지만, 더 나은 개념을 놓쳤을 가능성이 있으면
표시한다.

## 출력 형식

`mid1st/data/concept_assignments.jsonl`에 입력과 같은 순서로 정확히 1,200줄을 쓴다. 빈 줄, 주석,
마크다운 코드 펜스를 넣지 않는다. 각 줄은 아래 키만 갖는 JSON 객체다.

```json
{"wordId":"입력값 그대로","day":1,"no":1,"set":1,"word":"입력값 그대로","conceptId":"카탈로그의 정확한 ID 또는 null","matchMode":"direct","rationaleKo":"고정 뜻과 개념이 연결되는 이유","conceptCueKo":"예문에 구현할 구체적 사실이나 장면","confidence":"high","reviewRequired":false,"reviewReason":""}
```

필드와 enum은 다음과 같다.

- `wordId`, `day`, `no`, `set`, `word`: 입력 그대로
- `conceptId`: 카탈로그에 있는 정확한 문자열 ID 또는 `null`
- `matchMode`: `direct | contextual | day_fallback | word_fallback`
- `rationaleKo`: 단어 뜻과 배정의 관계를 짧고 구체적으로 설명
- `conceptCueKo`: 다음 단계가 문장에 직접 구현할 단서
- `confidence`: `high | medium | low`
- `reviewRequired`: boolean
- `reviewReason`: 검토가 없으면 빈 문자열, 있으면 구체적인 한 문장

`conceptId`가 있는 행은 `direct` 또는 `contextual`이어야 하고, `conceptId`가 `null`인 행은
두 fallback 중 하나여야 한다.

## 개념 사용량 산출물

배정 수치를 손으로 세지 않는다. `concept_assignments.jsonl` 초안을 쓴 뒤 아래 결정론적 도구로
`mid1st/data/concept_usage.json`을 만든다.

```powershell
node mid1st/scripts/build-concept-usage.mjs
```

이 파일은 아래 최상위 키와 concepts item 키만 사용하는 strict JSON 객체다. 도구가 카탈로그의
153개 개념을 원래 순서대로, 사용 0회인 항목까지 모두 포함한다.

```json
{
  "schemaVersion": 1,
  "totalWords": 1200,
  "curriculumAssignedWords": 0,
  "fallbackWords": 0,
  "actualMeanPerConcept": 0,
  "subjectCounts": {
    "korean": 0,
    "mathematics": 0,
    "science": 0,
    "social_studies": 0
  },
  "matchModeCounts": {
    "direct": 0,
    "contextual": 0,
    "day_fallback": 0,
    "word_fallback": 0
  },
  "concepts": [
    {
      "conceptId": "카탈로그 ID",
      "count": 0,
      "directCount": 0,
      "contextualCount": 0
    }
  ],
  "unusedConceptIds": [],
  "lowUseConceptIds": [],
  "overusedConceptIds": [],
  "balanceReviewNotesKo": []
}
```

- `actualMeanPerConcept`는 `curriculumAssignedWords / 153`으로 계산한다.
- `subjectCounts`는 catalog의 `subject` 값인 `korean`, `mathematics`, `science`,
  `social_studies` 네 키를 정확히 사용한다. 합은 `curriculumAssignedWords`와 같아야 한다.
- `matchModeCounts`는 네 matchMode 키를 모두 쓰며 합이 1,200이어야 한다.
- `unusedConceptIds`는 0회인 개념이다.
- `lowUseConceptIds`는 사용량이 0보다 크고 `actualMeanPerConcept × 0.5`보다 작은 개념이다.
- `overusedConceptIds`는 사용량이 `actualMeanPerConcept × 2`보다 큰 개념이다.
- 미사용·저사용·과다사용 목록은 재검토 목록이지 실패 목록이나 할당 지시가 아니다.
- `balanceReviewNotesKo`에는 미사용·저사용 개념을 검토했지만 정확한 단어가 없어 유지한 경우와,
  과다 사용 개념에서 동등한 대안으로 옮긴 경우를 요약한다.
- 개념별 `count`의 합은 `curriculumAssignedWords`와 같아야 하고, direct/contextual 합도 각
  `count`와 같아야 한다.

사용량 파일을 맞추기 위해 배정을 바꾸지 않는다. 배정의 의미 품질을 먼저 확정한 뒤 사용량을
그대로 집계한다. 생성 도구가 계산한 수치와 ID 목록은 손으로 수정하지 않는다.
`balanceReviewNotesKo`만 의미 품질을 검토한 사람이 짧은 메모를 추가할 수 있다.

## 완료 전 검증

```powershell
node mid1st/scripts/build-concept-usage.mjs
node mid1st/scripts/validate-assignments.mjs `
  --report mid1st/reports/assignment-validation.md
```

첫 실행의 검증 보고서와 사용량 파일로 미사용·저사용·과다사용 개념을 다시 검토한다. 의미·
직접성·사실성이 동등한 대체만 배정에 반영한다. 배정을 바꿨다면 이 세션이 방금 만든 파생
사용량 파일만 다음처럼 결정론적으로 갱신한다.

```powershell
node mid1st/scripts/build-concept-usage.mjs --force
```

그 뒤 `balanceReviewNotesKo`에 실제 균형 검토 결과를 기록하고 validate 명령을 최종적으로 한
번 더 실행한다. FAIL이 있으면 배정 파일을 고치고 사용량 파일도 다시 생성한 뒤 재검증한다.
다음을 확인한다.

- 정확히 1,200개이고 모든 identity가 입력과 일치한다
- 존재하지 않는 `conceptId`가 없다
- 고정 뜻·품사·정의를 변경한 산출물이 없다
- 개념별·과목별 사용량과 fallback 수가 집계된다
- 0회 및 낮은 사용 개념을 검토했지만 억지 재배정은 하지 않았다
- `reviewRequired` 항목과 이유가 남아 있다

형식 검증은 의미 정확성이나 교과 사실성을 대신하지 않는다. 최종적으로 사람이 검토할 수
있도록 검토 항목을 숨기지 않는다.
