# P2 — 공통 배정으로 예문 후보 만들기

## 목적

`codex`, `antigravity`, `claude`가 **동일한 단어 입력, 동일한 교과 개념 배정, 동일한 품질
규칙**으로 1,200개 예문을 각각 만든다. 세 모델은 예문만 경쟁하며, 단어의 뜻이나 배정된
개념을 바꾸지 않는다.

## 선행 조건

아래 파일이 모두 준비되고 검증을 통과한 뒤에만 전량 생성을 시작한다.

- `mid1st/data/word_inventory.jsonl`
- `mid1st/data/concept_catalog.json`
- `mid1st/data/concept_assignments.jsonl`
- `mid1st/data/sets/`의 120개 입력 세트
- 사용자 선택이 반영된 `mid1st/calibration/selected_examples.jsonl`

`concept_assignments.jsonl`이 없거나 assignment 검증이 실패하면 각 모델이 임의로 개념을
배정하지 말고 중단한다. `selected_examples.jsonl`이 없거나 유효한 선택이 6개 미만이면 P0
대표 샘플 보정을 먼저 끝낸다. 6~12개 선택이면 충분하며 24개 전부를 요구하지 않는다.

```powershell
node mid1st/scripts/validate-calibration-selection.mjs --max 12 `
  --report mid1st/reports/calibration-selection-validation.md
```

위 검증도 통과해야 전량 생성을 시작할 수 있다.

## 변경할 수 없는 것

각 단어의 다음 항목은 확정 입력이다.

- `wordId`, `day`, `no`, `set`, `word`
- `partOfSpeech`, `meaningKo`, `ipa`, `definition`
- PART·DAY 주제
- P1의 `conceptId`, `matchMode`, `rationaleKo`, `conceptCueKo`

이 단계의 유일한 창작 필드는 `sentence`다. 확정 뜻과 품사가 어렵거나 배정이 약해 보여도
다른 뜻·품사·개념을 택하지 않는다. 문제가 있으면 해당 author의 `run_report.md`에
`wordId`와 이유를 기록하고, 주어진 입력 안에서 가장 정확한 문장을 만든다.

## 예문 필수 규칙

모든 문장은 아래 조건을 동시에 만족해야 한다.

1. 영어 **8~12단어**다.
2. `word`의 표제어 철자를 그대로 포함한다.
3. 표제어를 복수형, 과거형, 3인칭 단수형, 비교급, 소유격 등으로 굴절시키지 않는다.
4. 표제어는 `meaningKo`·`partOfSpeech`·`definition`이 확정한 뜻의 자연스러운 대표
   용법으로 쓴다.
5. 한국 초등학교 6학년이 문장 구조와 일반 어휘를 읽을 수 있게 쓴다.
6. 내용은 중1 교과 맥락을 담되 어려운 전문용어를 나열하지 않는다.
7. 단어의 뜻과 배정된 교과 개념이 문장 자체에서 모두 직접 확인된다.
8. 한 문장에 한 가지 사실·관찰·측정·분류·계산·행동만 담는다.
9. 문장 하나만 읽어도 독립된 장면이나 과정이 선명하다.
10. 사실에 맞고 안전하며 나중에 한 장의 이미지로 만들 수 있다.

표제어가 문두에서 대문자로 변하는 일을 피할 수 있으면 문장 중간에 둔다. 대소문자까지
검사하는 검증기를 통과할 수 있도록 입력 철자를 그대로 쓰는 것이 가장 안전하다. 구동사나
복합 표현이면 입력의 공백과 철자를 유지한다.

## 교과 연결을 문장에 드러내는 법

`conceptCueKo`를 문장 속 구체적인 대상과 관계로 구현한다. 개념 이름만 말하지 말고 학생이
그 개념을 확인할 수 있는 증거를 넣는다.

- 관찰: 어떤 물체·생물·자료에서 무엇이 변하거나 유지되는지 보인다.
- 측정: 무엇을 어떤 기준이나 도구로 비교하는지 보인다.
- 분류: 어떤 공통 성질 때문에 같은 무리인지 보인다.
- 계산: 어떤 수량 관계나 연산을 하는지 보인다.
- 사회·국어: 구체적인 발언, 자료, 규칙, 관계, 행동으로 개념을 보인다.

“수업에서 이 단어를 배웠다”는 식의 문장은 금지한다. 교과명이 없어도 개념이 드러나는
문장이 더 좋다.

- 나쁨: `We discuss gravity during our interesting science class today.`
  - 단어와 과목 이름만 있고 중력 현상이 없다.
- 좋음: `A dropped ball falls because gravity pulls it toward Earth.`
  - 단어의 뜻과 낙하 방향이 직접 보인다.
- 나쁨: `Her bright idea was a seed growing in her mind.`
  - 개념 연결이 은유다.

`day_fallback`은 DAY 주제와 단어 뜻을 문자 그대로 보여주고, `word_fallback`은 교과 요소를
억지로 넣지 말고 단어 뜻이 가장 선명한 자연스러운 장면을 쓴다.

## 비유 표현 금지

표제어뿐 아니라 문장 전체를 가능한 한 문자 그대로 쓴다.

- 은유, 비유, 상징, 관용적 전용, 시적 의인화 금지
- `like`나 `as`를 사용한 비유로 개념을 연결하지 않는다
- “마음의 씨앗”, “시간이 달린다”, “사회가 아프다” 같은 표현 금지
- 교과 개념을 판타지 장치나 마법으로 바꾸지 않는다

부정적 뜻을 안전하게 보여주기 위한 동물·사물·게임 상황은 허용하지만, 그 상황에서도 표제어의
뜻은 문자 그대로 확인되어야 한다.

## 사실성·안전성·장면성

- 중1 교과 자료가 말하는 범위를 넘는 단정이나 잘못된 인과관계를 만들지 않는다.
- 숫자를 쓰면 계산과 단위가 맞아야 한다. 화면 속 숫자나 글자를 읽어야만 이해되는 장면은
  피한다.
- 상표, 로고, 유명 작품, 유명 캐릭터, 실존 유명인에 의존하지 않는다.
- 폭력, 피, 상처, 무기, 위협, 공포, 차별, 선정성, 모방 위험 행동을 피한다.
- 학생이 따라 하면 위험한 실험을 만들지 않는다.
- 사람 이름을 반복하거나 세트의 열 문장을 하나의 이야기로 잇지 않는다.
- 추상어는 행동·표정·사물의 상태로 뜻이 확인되게 한다.
- 불필요한 시간·색상·감탄 표현으로 단어 수만 채우지 않는다.

## 사용자 선택 예문 반영

`selected_examples.jsonl`은 사용자가 세 모델의 대표 샘플 중 고른 선호 신호다. 다음 성질을
추론해 전량에 일관되게 적용한다.

- 어느 정도로 구체적인 사물·행동을 선호하는가
- 교과 사실을 얼마나 직접적으로 드러내는가
- 쉬운 어휘와 자연스러운 문장 리듬
- 유머나 상상 요소를 어느 정도 허용하는가
- 뜻과 개념 중 무엇이 흐려질 때 어떤 방식으로 고쳤는가

그러나 선택 문장은 콘텐츠 템플릿이 아니다.

- 문장 구조, 주어, 사물, 장소, 수식어, 구절을 그대로 복제하지 않는다.
- 표제어만 바꾸는 패턴 복제를 하지 않는다.
- 선택 예문의 인물이나 장면을 다른 단어에 반복하지 않는다.
- 표면 문구가 아니라 사용자가 선호한 **판단 원칙**만 일반화한다.

## 자기 점검 순서

문장을 저장하기 전에 각 항목을 다음 순서로 점검하고 실패하면 다시 쓴다.

1. 표제어 철자가 정확히 들어갔는가
2. 확정 뜻과 품사로 쓰였는가
3. 8~12단어인가
4. `conceptCueKo`의 사실이나 관계가 실제 문장에 있는가
5. 교과 단어를 삭제해도 남는 일반 장면이 아니라, 개념이 의미에 필요한가
6. 비유·은유 없이 문자적인가
7. 초6이 읽을 문장 구조인가
8. 사실·안전·한 장면 조건을 지키는가
9. 같은 세트 문장들과 소재·주어·구조가 과도하게 반복되지 않는가

문장을 먼저 많이 만든 뒤 임의로 고르지 말고, 내부적으로 2~3개를 검토한 뒤 위 기준을 가장
잘 만족하는 한 문장만 저장한다. 내부 초안이나 사고 과정은 출력하지 않는다.

## 세트별 출력 형식

author에 따라 아래에 저장한다.

```text
mid1st/candidates/codex/DAYnn_ss-ee_setn/sentences.json
mid1st/candidates/antigravity/DAYnn_ss-ee_setn/sentences.json
mid1st/candidates/claude/DAYnn_ss-ee_setn/sentences.json
```

각 파일은 10개 단어를 입력 순서대로 담는다. strict 형식은 다음과 같다.

```json
{
  "schemaVersion": 1,
  "author": "codex",
  "day": 1,
  "range": "01-10",
  "set": 1,
  "items": [
    {
      "wordId": "입력값 그대로",
      "no": 1,
      "word": "입력값 그대로",
      "sentence": "8~12단어의 최종 예문"
    }
  ]
}
```

최상위 키는 `schemaVersion`, `author`, `day`, `range`, `set`, `items`만 쓴다. item 키는
`wordId`, `no`, `word`, `sentence`만 쓴다. 뜻, 개념, 근거, 점수, 검토 메모를 후보 파일에
추가하지 않는다. `author`만 모델별 값으로 바꾸며 나머지 형식과 품질 조건은 세 모델 모두
같다.

## 재개와 보고

- 이미 검증을 통과한 세트는 덮어쓰지 않는다.
- 중단 후에는 누락되었거나 검증에 실패한 세트만 작성한다.
- 입력 자체의 문제로 판단한 항목은 결과를 빼지 말고 최선의 문장을 만든 뒤
  `mid1st/candidates/<author>/run_report.md`에 기록한다.
- `run_report.md`에는 완료 세트 수, 검증 결과, 판단이 어려운 `wordId`, 반복적으로 발견된
  문제 유형만 쓴다. 장황한 생성 과정은 쓰지 않는다.

## 완료 전 검증

author를 바꾸어 실행한다.

```powershell
node mid1st/scripts/validate-candidates.mjs --author codex `
  --report mid1st/candidates/codex/validation_report.md
```

FAIL이 하나라도 남으면 해당 세트만 수정해 다시 검사한다. 형식 검증을 통과해도 다음은 직접
샘플링해 확인한다.

- 단어 뜻과 개념이 둘 다 문장에 선명하다
- 단순히 과목명만 붙인 문장이 없다
- 비유·은유가 없다
- 선택 예문의 표면 패턴을 복제하지 않았다
- 개념별로 장면과 문장 구조가 과도하게 획일화되지 않았다

세 모델의 후보를 비교할 때는 문법적 화려함보다 **단어의 고정 뜻과 공통 교과 개념이 가장
직접적이고 선명하게 드러나는 문장**을 고른다.
