# P3 — baseline과 세 모델 예문을 단어별로 선별

## 목적

확정된 단어 뜻과 공통 교과 개념을 기준으로 `baseline`, `codex`, `antigravity`, `claude`의
문장을 단어별로 비교한다. 사용자에게서 받은 대표 선택 6~12개의 성향을 판단 원칙으로 삼아,
단어 뜻과 교과 개념이 가장 직접적이고 선명한 문장을 추천한다.

표현만 조금 다른 유사 후보는 자동 추천하고, 의미·개념 해석이 크게 갈리거나 네 문장이 모두
약한 항목만 사람 검토 보고서에 모은다.

## 입력 게이트

아래 입력이 모두 준비되어야 한다.

- `mid1st/data/word_inventory.jsonl`
  - 확정 뜻·품사·definition과 `baselineSentence`
- `mid1st/data/concept_catalog.json`
- 검증된 `mid1st/data/concept_assignments.jsonl` 1,200개
- 검증된 세 모델 후보 각 1,200개
  - `mid1st/candidates/codex/`
  - `mid1st/candidates/antigravity/`
  - `mid1st/candidates/claude/`
- 사용자 선택 `mid1st/calibration/selected_examples.jsonl` 6~12개

하나라도 누락되거나 검증에 실패하면 부분 선별을 시작하지 않는다. 한 모델의 누락을 baseline
또는 다른 모델로 자동 채우지 않는다.

## 사용자 성향 적용

`selected_examples.jsonl`의 선택 author 자체보다 `preferenceNoteKo`와 선택된 문장의 관찰 가능한
특징을 본다.

- 단어 뜻을 어떤 행동·상태·관계로 선명하게 보여주었는가
- 교과 사실을 과목명 없이 어느 정도 직접 드러냈는가
- 쉬운 어휘, 구체성, 문장 리듬, 장면 밀도는 어떠한가
- 사용자가 애매한 문장 대신 어떤 종류의 문장을 골랐는가

특정 author가 대표 샘플에서 많이 선택됐다는 이유로 그 author를 전량 우대하지 않는다.
선택 문장의 주어·구조·장소·사물·수식어·구절을 복제해 새 문장이나 수정안을 만들지 않는다.
사용자의 **판단 기준**만 일반화한다.

## 단어별 선별 우선순위

각 단어에서 아래 순서대로 판단한다. 앞의 기준을 희생해 뒤의 기준을 얻지 않는다.

1. 확정 `meaningKo`, `partOfSpeech`, `definition`과 정확히 같은 뜻인가
2. 표제어 철자를 그대로 자연스럽게 사용했는가
3. 공통 `conceptId`와 `conceptCueKo`의 사실·관계가 문장에서 직접 확인되는가
4. 비유·은유·상징이 아니라 문자적인 연결인가
5. 교과 사실과 영어 문법이 정확한가
6. 초6이 읽기 쉽고 8~12단어인가
7. 안전하고 한 장면이나 한 과정으로 시각화하기 쉬운가
8. 위 품질이 동률일 때 사용자 대표 선택의 성향과 더 가까운가

`day_fallback`에서는 DAY 주제와 단어 뜻, `word_fallback`에서는 단어 뜻의 직접성을 본다.
fallback에 교과 연결이 없다는 이유로 감점하지 않는다. 억지 교과 연결보다 정직한 fallback을
선호한다.

baseline도 네 번째 동등한 후보다. 기존 문장이라는 이유로 우대하거나 배제하지 않는다.
author 이름, 문체의 화려함, 유머의 양은 뜻·개념의 직접성보다 앞설 수 없다.

## 자동 추천과 사람 검토의 경계

### 자동 추천

다음 경우는 사용자에게 묻지 않고 가장 선명한 하나를 추천한다.

- 여러 후보가 같은 뜻과 같은 교과 관계를 문자 그대로 표현하고 차이가 주로 어순·소재다
- 한 후보가 다른 후보보다 뜻·개념·자연스러움에서 분명히 우수하다
- 일부 후보가 형식이나 직접성에서 탈락하고 남은 하나가 모든 기준을 충족한다
- 사용자 선호는 동률을 깨는 정도이며 의미 선택을 바꾸지 않는다

문장이 서로 다르다는 이유만으로 검토 대상으로 만들지 않는다.

### `reviewRequired`

다음 경우만 `mid1st/reports/selection-review.md`에 넣는다.

- 후보들이 확정 뜻이나 품사를 서로 다르게 해석한다
- 단어 뜻은 좋은 후보와 교과 개념은 좋은 후보가 달라 뚜렷한 절충이 필요하다
- 교과 사실의 정확성이나 자연스러운 영어 여부가 확실하지 않다
- 비유 여부, 안전성, exact word의 자연스러운 용법에 실질적인 의문이 있다
- baseline과 세 모델 후보가 모두 하나 이상의 핵심 기준을 위반한다
- 수동 수정안이 필요하거나 두 후보의 의미 차이가 커 사용자 성향만으로 결정하면 위험하다

검토 항목에도 현재 가장 나은 추천은 manifest에 넣되, `note`를
`reviewRequired: <짧은 이유>`로 시작한다. 네 후보가 모두 약하면 8~12단어의 문자적 수정안을
만들어 `selectedAuthor: "manual"`로 추천하고 반드시 검토 보고서에 넣는다.

## 비교 자료 만들기

세 모델 후보 검증이 모두 통과한 뒤 다음을 실행한다.

```powershell
node mid1st/scripts/compare-candidates.mjs
```

기본 비교표 `mid1st/comparisons/all.md`에는 단어 뜻·definition, 공통 개념·cue, baseline,
세 모델 후보가 나란히 나온다. 비교표가 이미 있으면 입력과 일치하는지 확인하고, 임의로
덮어쓰지 않는다.

## 선택 manifest

`mid1st/final/selection_manifest.jsonl`에 inventory 순서대로 정확히 1,200줄을 쓴다. 빈 줄,
코드 펜스, 주석을 넣지 않는다. 각 줄은 아래 네 키만 가진다.

기존 manifest가 있으면 임의로 덮어쓰지 않는다. 이미 유효한 1,200개면 dry-run 결과만
보고하고, 불완전하거나 검토 중인 파일이면 현재 내용을 보존한 채 사용자에게 재작업 범위를
확인한다. 같은 신규 실행 안에서 방금 만든 manifest의 검증 오류를 고치는 것은 허용한다.

```json
{"wordId":"DAY01-01","selectedAuthor":"codex","sentenceOverride":null,"note":"auto: 단어 뜻과 교과 관계가 가장 직접적임"}
```

strict 규칙:

- `selectedAuthor`: `codex | antigravity | claude | baseline | manual`
- 후보 하나를 고르면 `sentenceOverride`는 반드시 `null`
- `manual`이면 `sentenceOverride`에 최종 수정 문장을 넣는다
- `manual`이 아닌데 후보 문장을 복사해 override에 넣지 않는다
- `note`: 고확신 추천은 `auto:`, 사람 확인 필요는 `reviewRequired:`로 시작하는 짧은 한국어
  근거
- 선택한 author의 실제 문장을 고쳐 쓰지 않는다. 수정이 필요하면 `manual`을 쓴다

## 사람 검토 보고서

`mid1st/reports/selection-review.md`에는 `reviewRequired` 항목만 inventory 순서로 모은다.
이미 사용자가 답을 기록한 검토 보고서를 덮어쓰지 않는다.

각 항목에는 다음을 포함한다.

- `wordId`, word, 확정 한국어 뜻·품사·definition
- PART·DAY 주제
- 공통 개념 이름, `matchMode`, `conceptCueKo`
- baseline·codex·antigravity·claude 문장
- 현재 추천과 검토가 필요한 구체적인 이유
- manual 수정안이 있으면 그 문장

보고서 맨 위에는 전체 1,200개 중 자동 추천 수, 검토 필요 수, author별 추천 수, manual 수를
요약한다. 후보 차이가 작다는 이유만으로 표를 늘리지 않는다.

## 검증과 최종 생성 게이트

manifest를 쓴 뒤 다음 dry-run으로 identity, strict schema, 선택 문장, exact word, 8~12단어를
검증한다.

```powershell
node mid1st/scripts/build-final.mjs --dry-run
```

FAIL이 있으면 manifest를 고치고 다시 실행한다. `selection-review.md`에 항목이 남아 있으면 실제
최종 파일을 만들지 말고 사용자의 선택·수정안 승인을 기다린다. 사용자가 검토 항목을 해결하거나
현재 추천을 일괄 승인한 뒤에만 다음을 실행한다.

```powershell
node mid1st/scripts/build-final.mjs
```

최종 산출물은 `mid1st/final/final_sentences.jsonl`이다. 기존 원본의 sentence를 덮어쓰지 않는다.
